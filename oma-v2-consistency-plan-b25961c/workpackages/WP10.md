## 1. 이 작업이 필요한 이유와 판정의 강도

Resident adapter는 idleStreamSeconds로 전체 delivery의 절대 deadline을 만든다. source에는 model inferenceTimeoutSeconds도 있지만 해당 경로의 budget이 무엇인지 일관된 계약이 필요하다. 동시에 shutdown grace, stdout close, child exit, cgroup death를 하나의 종료 bool로 합치면 기존 강한 fencing을 잃는다.

## 3. 구현 순서 — 아래 소작업 단위로 커밋을 분리한다

### WP10.01 — budget 출처 표

partial JSONL/frame idle, stdin write, prompt acceptance, 전체 model turn, shutdown drain, restart window의 출처·단위·clock·owner를 표로 만든다. 기존 field로 의미가 맞는지 확인하고 새 wire/config field가 필요하면 ADR을 먼저 갱신한다.

### WP10.02 — timer primitive 선택

기존 rearming alarm을 재사용할 수 있는 경계를 확인한다. monotonic clock과 cancel semantics를 공통화하되 서로 다른 budget을 하나로 합치지 않는다. 0x7fffffff 초과를 단순 clamp해 계약보다 일찍 timeout시키지 않는다.

### WP10.03 — cancel 결과의 정확성

runner stop에서 transport만 닫히는지 실제 owned engine/relay가 끝나는지 점검한다. result Promise 완료, child exit, stdio close, arbitrary descendant 종료를 분리해 책임을 연결한다. native 불명은 writer-resource 보존 정책을 유지한다.

### WP10.04 — generation-bound registration

supervisor pending registration과 tenure live state를 해당 broker generation에 묶는다. 늦은 credential·refusal·timeout이 새 generation에 적용되지 않도록 final callback 시점에서도 확인한다.

### WP10.05 — cleanup과 shutdown convergence

신규 timer/listener/task의 생성·취소·종료 지점을 표로 남긴다. 종료를 반복 호출해도 같은 Promise/동일 결과로 수렴하도록 하고 stop 도중 새 engine을 시작하는 경로를 막는다.

## 4. 회귀 시험 — production 경로를 사용한다

### V10A — idle/accept/turn/drain deadline 분리

**준비:** Resident와 Principal adapter, 제어된 실제 subprocess, 여러 정상 event

**동작:** 정상 progress는 계속되지만 전체 turn이 30초를 넘는 경우와 실제 partial-line idle을 각각 실행한다.

**관측해야 할 결과:** 선언한 deadline별로 서로 다른 결과를 내고 idle budget을 전체 turn budget으로 오용하지 않는다.

**음성 대조군:** 모든 timer를 idleStreamSeconds에 연결하는 control이 실패한다.

**lane / 현재 실행 상태:** `durable` / `NOT_RUN`.
### V10B — writer shutdown은 native 불명에서 lock을 보존

**준비:** PreparationExecutor가 non-exited observation을 반환하고 native closure가 남은 상태

**동작:** BrokerLifetime.shutdown grace를 만료시킨다.

**관측해야 할 결과:** Store/lock을 먼저 풀지 않고 명시적 termination 요구를 낸다. direct child exit와 descendant quiescence를 구분한다.

**음성 대조군:** timeout=resolved-success로 바꾸거나 준비 barrier를 생략하면 실패한다.

**lane / 현재 실행 상태:** `kernel` / `NOT_RUN`.
### V10C — registration generation과 timer 정리

**준비:** broker generation A에서 registration pending, B로 restart, late response A

**동작:** 응답·timeout·close를 여러 순서로 전달하고 active timer/observer 수를 관측한다.

**관측해야 할 결과:** A의 응답은 B의 권한을 만들지 않고 종료 후 timer/observer가 늘지 않는다. long deadline은 native timer overflow로 즉시 만료되지 않는다.

**음성 대조군:** generation 비교 제거와 cancel 누락 각각을 검출한다.

**lane / 현재 실행 상태:** `property` / `NOT_RUN`.

시험 ID는 이 계획의 새 ID다. 같은 이름의 test 파일이 이미 존재한다고 가정하지 않는다. 기존 시험이 동일 계약을 검증하면 중복 파일 대신 확장하고, [테스트 원장](../verification/TEST-CATALOG.md)에 실제 파일·case 이름을 연결한다. 모형만 통과한 결과는 production 통합 증거가 아니다.

## 5. 금지하는 해결법

clock overflow 무시, 모든 deadline을 넉넉한 상수로 늘림, timeout을 child death로 간주, `unref()`를 종료 증명으로 사용, shutdown 완료를 위해 Store/lock을 먼저 해제하는 것을 금지한다.

## 6. 호환성·실패·롤백

C1/C2. timeout 정책 변경은 사용자 동작을 바꾸므로 D06과 기존 profile 계약에 명시한다. 엔진 비용 제한을 새로 집행한다고 주장하지 않는다. deployment/engine upgrade와 한 commit에 섞지 않는다.

작업 중간에 실행 자료가 없으면 `BLOCKED` 또는 `NOT_RUN`으로 기록한다. 코드 revert는 영속 상태 rollback과 같지 않다. DB·receipt·configuration generation을 바꾼 뒤 과거 바이너리를 재실행하려면 [호환성 표](../guide/COMPATIBILITY.md)를 먼저 적용한다.

## 7. 완료 판정과 다음 AI에게 넘길 것

budget 출처와 각 종료 사건이 한 의미로 사용된다. 지원된 mode에서 정상 긴 턴/진짜 idle/늦은 등록/불명 native 작업을 구분하는 시험이 통과한다.

공통 필수 증거: 변경 전후 HEAD와 input digest, 변경 파일, Fact/Relation/Phase, 실제 시험 명령·종료 코드·skip 수, 원본으로 되돌렸을 때 깨지는 회귀 시험, 남은 미검증 범위. [handoff 양식](../templates/HANDOFF.md)을 채운다. `npm run typecheck`, `npm run build`, 관련 시험을 통과한 뒤 해당 commit의 architecture/inventory 상태를 확인한다. 정확한 종합 순서는 [검증 실행 규율](../verification/RUNBOOK.md)을 따른다.
