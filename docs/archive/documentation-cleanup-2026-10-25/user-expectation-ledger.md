# 사용자 기대 미충족 장부

## 2026-10-09 지정 변경

Human 지시로 SC-01~05/20/31의 네트워크·실행 자원·quota 제한을 제거했다.
SC-23은 MCP 설치/인증/CA/명령 helper, SC-26은 웹 clone/미디어/curator/answer/명령을 복구했다.
SC-30은 실제 reader flock 기반 회수, SC-32는 input을 막지 않는 fd 설치와 기존 provider 갱신으로
해결했다. 최종 local 3,946·kernel 68·crash 63 PASS이며 실행과 native 미실행 범위는
[validation](implementation/validation.md)과 [DR37 evidence](../test/audit/unrestricted-2026-10-09.evidence.json)를 따른다.
아래 32개 표는 변경 전 조사 원문이며 현재 정책은 DR37과 validation을 따른다.
구버전 독자를 증명할 수 없는 marker 없는 package 세대는 자동 수거에서 보존한다.

## 이전 조사: 변경 전 사용자가 예상하기 어려운 제약 (2026-10-09)

사용자가 인터넷 차단·skills 적용 불가 등을 포함해 제약을 전반적으로 찾으라고 요청했다.
아래는 변경 전에 확인한 동작이다. 과거 “수정됨”은 무제한 사용 가능이라는 뜻이 아니다.
특히 UX-08의 프록시 구현과 **기본 인터넷 허용**은 다르다. 의도된 격리도 조사에서 제외하지
않았다. 근거는 로컬 생산 코드이며, Linux 실행 재현과 native macOS/외부 서비스별 검증의
범위는 별도 validation 기록을 따른다. 이 추가 요청은 발견·기록이며, 기존 13건의 수정 결과는
감사 기록과 validation이 소유한다. 아래 32건이 외부 서비스별 실행 증명이나 모든 제약의 부재를 뜻하지 않는다.

기본 차단, 설정 가능한 제한, 설정으로 해제할 수 없는 제한을 혼동하지 않는다. 이 표의
사실을 숨기거나 “인터넷/skills 완전 지원”으로 과장하지 않으며, authority·격리 경계도
근거 없이 제거하지 않는다.

> 사용자가 당연히 될 거라 기대하는데 안 되는 것(WORKSTREAM §2 기준 1·2·9·10·11 중심)을
> 발견 → 결정 → 수정 순으로 기록한다. 내부 원인이어도 사용자가 겪으면 여기 올리고 구현한다.
> 사용자에게 영향 없는 순수 기술개선은 여기 올리지 않는다(WORKSTREAM에 기록만).
> 전체 작업이 끝나면 이 장부로 사용자에게 "무엇을 더 찾았고 어떻게 고쳤는지" 보고한다.

상태: `발견` → `결정` → `구현 중(브랜치)` → `수정됨(커밋, 테스트)` → `검증됨`
