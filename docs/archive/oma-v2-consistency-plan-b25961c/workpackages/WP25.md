## 1. 이 작업이 필요한 이유와 판정의 강도

현재 lifecycle은 frozen previousIncarnation과 현재 run을 구별하고, RunRegistry는 실제 pinned cgroup의 죽음을 관측한다. 새 전달 복구·배포 topology·deadline 수정이 이 보장을 약화시키지 않아야 한다. source별 국소 성공을 실제 프로세스 수명 보장으로 과대 해석하지 않는다.

## 3. 구현 순서 — 아래 소작업 단위로 커밋을 분리한다

### WP25.01 — 권한과 identity 표

actor/name/incarnation/InvocationID/cgroup pin/peer liveness/society lease가 각각 무엇을 증명하는지 기록한다. terminal operation 조회와 lifecycle method의 현재 관리 권한 요구를 명시적으로 구별한다. string actor를 모든 권한의 대용으로 쓰지 않는다.

### WP25.02 — lifecycle transition 검토

start/stop/create/ready/activation의 normal/recovery 분기를 실제 source에서 따라간다. old action이 더 새로운 desired/incarnation을 대상으로 새 effect를 낼 수 없게 한다. logical stop acceptance와 물리 종료 증명을 분리한다.

### WP25.03 — unit rendering과 frozen 정책

WP03 launch contract를 모든 relevant unit에 적용한다. 시작 시 적용할 model 선택과 immutable accepted resource/spec의 의미를 D05에 맞춰 구분한다. model 변경 편의를 위해 frozen resource/capability를 현재 설정으로 몰래 대체하지 않는다.

### WP25.04 — 핀의 소유권과 teardown

revoke가 authorization을 닫고 death 관측까지 pin은 남는 기존 수명을 유지한다. 신호·exit·stdio close·cgroup empty의 서로 다른 사실을 연결하고 shutdown timeout에서 writer resources를 premature release하지 않는다. 누수는 failure reason과 함께 끝까지 관측한다.

### WP25.05 — kernel 결합

fresh disposable user 환경에서 product/systemd 두 지원 topology의 bootstrap, run, stop, broker loss, restart gap을 확인한다. unit manager가 없는 모형 시험은 분기 oracle일 뿐 kernel 보장의 증거로 쓰지 않는다.

## 4. 회귀 시험 — production 경로를 사용한다

### V25A — 오래된 start/stop이 새 run을 제어하지 못함

**준비:** 정상 agent와 old accepted start/stop, 이후 새 incarnation의 실제 user-systemd run

**동작:** old key 조회/재시도/reconcile과 현재 명시적 stop을 각각 수행한다.

**관측해야 할 결과:** old intent는 새 incarnation에 효과를 내지 않고 current action은 현재 권한 아래 동작한다. terminal action replay의 기존 D06 관리 권한 요구를 유지한다.

**음성 대조군:** previousIncarnation을 현재 값으로 보정하거나 old stop을 새 service에 재발행하면 실패한다.

**lane / 현재 실행 상태:** `kernel` / `NOT_RUN`.
### V25B — 일부 실패 후 safety cleanup과 pin 수명

**준비:** path disable 실패, endpoint revoke, service stop, cgroup death observation의 제어된 실패 조합

**동작:** stop/shutdown/restart를 실행하고 호출 결과와 실제 pin/FD/descendant 상태를 기록한다.

**관측해야 할 결과:** 한 실패 때문에 나머지 안전 조치가 생략되지 않는다. 죽음 불명은 success가 아니고 pin/lease를 성급히 버리지 않는다.

**음성 대조군:** 첫 예외에서 전체 cleanup 중단 또는 signal 송신을 death로 취급하는 control이 실패한다.

**lane / 현재 실행 상태:** `kernel` / `NOT_RUN`.

시험 ID는 이 계획의 새 ID다. 같은 이름의 test 파일이 이미 존재한다고 가정하지 않는다. 기존 시험이 동일 계약을 검증하면 중복 파일 대신 확장하고, [테스트 원장](../verification/TEST-CATALOG.md)에 실제 파일·case 이름을 연결한다. 모형만 통과한 결과는 production 통합 증거가 아니다.

## 5. 금지하는 해결법

pid 존재/kill 반환/socket 경로로 실제 권한·죽음 추정, cgroup read 실패를 empty, old incarnation을 현재 값으로 덮어쓰기, 모든 terminal replay에 일률적으로 auth 생략, 실패 unit을 무조건 reset-failed하는 것을 금지한다.

## 6. 호환성·실패·롤백

C0/C1. 이미 accepted된 action은 이전 incarnation을 유지한다. kernel lane 미실행이면 코드 변경 완료와 별개로 해당 수명 보장은 BLOCKED이며 release gate를 닫지 않는다.

작업 중간에 실행 자료가 없으면 `BLOCKED` 또는 `NOT_RUN`으로 기록한다. 코드 revert는 영속 상태 rollback과 같지 않다. DB·receipt·configuration generation을 바꾼 뒤 과거 바이너리를 재실행하려면 [호환성 표](../guide/COMPATIBILITY.md)를 먼저 적용한다.

## 7. 완료 판정과 다음 AI에게 넘길 것

lifecycle state/physical observation/lease lifetime이 같은 표에 연결된다. 기존 올바른 fences는 유지되고 신규 delivery/topology 변경과 결합한 실제 kernel oracle가 통과한다.

공통 필수 증거: 변경 전후 HEAD와 input digest, 변경 파일, Fact/Relation/Phase, 실제 시험 명령·종료 코드·skip 수, 원본으로 되돌렸을 때 깨지는 회귀 시험, 남은 미검증 범위. [handoff 양식](../templates/HANDOFF.md)을 채운다. `npm run typecheck`, `npm run build`, 관련 시험을 통과한 뒤 해당 commit의 architecture/inventory 상태를 확인한다. 정확한 종합 순서는 [검증 실행 규율](../verification/RUNBOOK.md)을 따른다.
