## 1. 이 작업이 필요한 이유와 판정의 강도

## 3. 구현 순서 — 아래 소작업 단위로 커밋을 분리한다

### WP14.01 — asset reference owner

normalized relative entry/extension suffix/size/regular file/core ordering/unique count를 loader 측 한 policy에 둔다. file observation은 adapter에서 수행하고 UI는 판정 결과와 이유를 표시한다. arbitrary path entry UI를 만들지 않는다.

### WP14.02 — enable pipeline

host-placed candidate 중에서만 선택하고 실제 asset observation과 전체 candidate validation을 수행한다. generation writer에 완전한 edit command를 넘겨 저장한다. role file 직접 쓰기를 제거한다.

### WP14.03 — disable recovery pipeline

이미 선언된 optional entry의 제거는 asset를 dereference하지 않아도 가능하게 한다. 안전한 layout과 raw authored source만 읽어 exact declaration 삭제 후보를 만든 뒤 full loader validation을 통과시킨다. 이 limited edit가 다른 무효 필드를 임의 보정하게 하지 않는다.

### WP14.04 — 보존해야 할 데이터

toolSurface, promptFile, agentProfile, 나머지 정상 extensions와 순서를 보존한다. enabling에 따른 code digest는 actual spawn 직전에 다시 확인한다. config generation이 external code까지 immutable하게 만든다고 주장하지 않는다.

### WP14.05 — scan bounds와 결과

directory depth뿐 아니라 항목 수/총 시간/bytes와 symlink traversal 정책을 정한다. scan이 일부만 수행됐으면 partial로 표시하고 candidate 목록의 완전성을 주장하지 않는다.

## 4. 회귀 시험 — production 경로를 사용한다

### V14A — UI가 켠 extension은 loader가 읽음

**준비:** host placed local JS/TS 후보와 내부 symlink·잘못된 참조·size/type boundary

**동작:** UI 선택→candidate validation→generation commit→loadConfiguration을 연속 실행한다.

**관측해야 할 결과:** 허용된 enable 결과는 loader가 받아들이고 거절은 파일 무변경이다. core는 첫 항목으로 유지된다.

**음성 대조군:** UI containedEntry와 loader localPath를 다시 독립 구현해 허용 집합이 달라지면 실패한다.

**lane / 현재 실행 상태:** `durable` / `NOT_RUN`.
### V14B — 사라진 optional extension을 안전하게 제거

**준비:** 기존 role에 선언됐지만 asset이 없어 loader가 실패하는 bundle; core는 정상

**동작:** 명시적으로 그 optional declaration을 disable한다.

**관측해야 할 결과:** 삭제는 해당 JSON 참조만 제거하고 candidate 전체가 valid일 때 commit한다. 없는 asset을 열려고 하지 않으며 core 제거는 계속 금지다.

**음성 대조군:** disable에도 asset read 성공을 요구하거나 arbitrary path를 writer target으로 쓰면 실패한다.

**lane / 현재 실행 상태:** `durable` / `NOT_RUN`.

시험 ID는 이 계획의 새 ID다. 같은 이름의 test 파일이 이미 존재한다고 가정하지 않는다. 기존 시험이 동일 계약을 검증하면 중복 파일 대신 확장하고, [테스트 원장](../verification/TEST-CATALOG.md)에 실제 파일·case 이름을 연결한다. 모형만 통과한 결과는 production 통합 증거가 아니다.

## 5. 금지하는 해결법

internal symlink를 UI에서만 허용, core 제거, missing asset 제거를 위해 전체 config validator 완화, toolSurface 블록 누락, selected digest를 secret 신뢰 증명으로 확대하는 것을 금지한다.

## 6. 호환성·실패·롤백

C1/C2. 무효 기존 설정의 repair는 명시적으로 해당 참조만 제거하는 편집이며 자동 정상화가 아니다. generation commit 전후 원본/새 snapshot을 보존한다.

작업 중간에 실행 자료가 없으면 `BLOCKED` 또는 `NOT_RUN`으로 기록한다. 코드 revert는 영속 상태 rollback과 같지 않다. DB·receipt·configuration generation을 바꾼 뒤 과거 바이너리를 재실행하려면 [호환성 표](../guide/COMPATIBILITY.md)를 먼저 적용한다.

## 7. 완료 판정과 다음 AI에게 넘길 것

enable된 모든 결과는 실제 loader를 통과하고 missing optional entry를 제거할 제한된 복구 경로가 있다. 모든 commit은 WP13으로 모이고 직접 role-file writer가 남지 않는다.

공통 필수 증거: 변경 전후 HEAD와 input digest, 변경 파일, Fact/Relation/Phase, 실제 시험 명령·종료 코드·skip 수, 원본으로 되돌렸을 때 깨지는 회귀 시험, 남은 미검증 범위. [handoff 양식](../templates/HANDOFF.md)을 채운다. `npm run typecheck`, `npm run build`, 관련 시험을 통과한 뒤 해당 commit의 architecture/inventory 상태를 확인한다. 정확한 종합 순서는 [검증 실행 규율](../verification/RUNBOOK.md)을 따른다.

추가 읽기: [CONFIG-CONTRACT](../decisions/CONFIG-CONTRACT.md). partial authored source와 runnable validated snapshot을 구별한다.
