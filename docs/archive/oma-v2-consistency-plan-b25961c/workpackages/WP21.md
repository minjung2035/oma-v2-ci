## 3. 구현 순서 — 아래 소작업 단위로 커밋을 분리한다

### WP21.01 — action taxonomy

existing mode/key/capability metadata를 읽고 resource category를 내부 descriptor로 연결한다. 공통 집합 하나로 두되 public wire에 새 field를 노출하지 않는다. `host.reconcile`은 복합 action이므로 내부 단계까지 분류한다.

### WP21.02 — guard 위치 이동

인증/버전/DTO/key 검증은 유지하고 quota 적용을 해당 action의 의미가 정해진 뒤로 이동한다. read와 historical receipt replay에 신규 resource reservation을 요구하지 않는다. unsupported/unknown method는 분류 fallback을 주지 않는다.

### WP21.03 — settlement 권한

valid receipt 정산과 새 filesystem/Git effect를 구분한다. recovery가 새 workspace/import/activation을 필요로 하면 admit/effect budget을 다시 확인한다. repair는 operator 전용 경계로 남기고 일반 client에게 열지 않는다.

### WP21.04 — error phase propagation

StoreError code만으로 결과를 분류하지 않고 accepted/nonaccepted/effect-possible 원인을 coordinator가 전달하게 한다. publicFailure sanitize와 terminal receipt 의미를 유지한다. UI readable message는 secret을 포함하지 않는다.

### WP21.05 — sticky integrity와 progress

STORE_CORRUPT가 새 admission을 닫는 기존 sticky gate를 보존한다. 진단은 그 이유를 읽을 수 있게 하고 corruption을 retryable absence로 바꾸지 않는다. stop/revoke는 일부 실패 후도 나머지 safety action을 수행한다.

## 4. 회귀 시험 — production 경로를 사용한다

### V21A — method category의 complete map

**준비:** PUBLIC_METHODS/INTERNAL_METHODS와 broker-owned recovery actions

**동작:** read/admit/settle/safety-control 분류에서 각 항목 누락 compile/runtime fixture를 확인한다.

**관측해야 할 결과:** 새 method/action 누락이 검출되며 read도 기존 authentication/DTO 검증을 유지한다.

**음성 대조군:** unknown method를 read로 defaulting하는 control이 실패한다.

**lane / 현재 실행 상태:** `fast` / `NOT_RUN`.
### V21B — quota가 기존 책임을 무조건 막지 않음

**준비:** storage admission 초과, accepted operation·prepared receipt·readable status

**동작:** operation.get/status와 new mutation, exact complete, safety stop을 실행한다.

**관측해야 할 결과:** read는 bounded 관측 결과, 신규 소비는 거절, 가능한 정산과 safety action은 자기 정책대로 진행한다. 실제 disk full 실패는 보존·보고한다.

**음성 대조군:** outer dispatch에서 모든 요청을 같은 quota guard로 차단하거나 reconcile 전체를 무제한 허용하면 실패한다.

**lane / 현재 실행 상태:** `durable` / `NOT_RUN`.

시험 ID는 이 계획의 새 ID다. 같은 이름의 test 파일이 이미 존재한다고 가정하지 않는다. 기존 시험이 동일 계약을 검증하면 중복 파일 대신 확장하고, [테스트 원장](../verification/TEST-CATALOG.md)에 실제 파일·case 이름을 연결한다. 모형만 통과한 결과는 production 통합 증거가 아니다.

## 5. 금지하는 해결법

read라서 인증 생략, recovery라서 모든 quota/capability 생략, retry string만 바꿔 문제 해결, new method의 default 허용, Store corruption을 가용성 이유로 무시하는 것을 금지한다.

## 6. 호환성·실패·롤백

C1/C2 admission 정책. DB/wire code 추가 없이 기존 오류 분류를 우선 사용한다. 예상 오류 precedence 변경은 fixture와 문서로 명시한다.

작업 중간에 실행 자료가 없으면 `BLOCKED` 또는 `NOT_RUN`으로 기록한다. 코드 revert는 영속 상태 rollback과 같지 않다. DB·receipt·configuration generation을 바꾼 뒤 과거 바이너리를 재실행하려면 [호환성 표](../guide/COMPATIBILITY.md)를 먼저 적용한다.

## 7. 완료 판정과 다음 AI에게 넘길 것

모든 method/action이 닫힌 category에 연결되고 admission 초과 상태에서 read/settle/safety/new work가 각기 정한 결과를 낸다. 오류 phase가 public receipt 의미와 일치한다.

공통 필수 증거: 변경 전후 HEAD와 input digest, 변경 파일, Fact/Relation/Phase, 실제 시험 명령·종료 코드·skip 수, 원본으로 되돌렸을 때 깨지는 회귀 시험, 남은 미검증 범위. [handoff 양식](../templates/HANDOFF.md)을 채운다. `npm run typecheck`, `npm run build`, 관련 시험을 통과한 뒤 해당 commit의 architecture/inventory 상태를 확인한다. 정확한 종합 순서는 [검증 실행 규율](../verification/RUNBOOK.md)을 따른다.
