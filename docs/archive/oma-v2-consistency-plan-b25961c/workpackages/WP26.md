## 1. 이 작업이 필요한 이유와 판정의 강도

CLI는 frozen request 재전송의 좋은 기준이지만 새로운 config/delivery 정책이 도입돼도 그 의미가 보존되는지 결합 검증해야 한다. 전수 검토 범위에는 protocol codec·method descriptor·frame budget·CLI command별 effect와 exit contract를 모두 포함한다.

## 3. 구현 순서 — 아래 소작업 단위로 커밋을 분리한다

### WP26.01 — 경계 전체 inventory

production inventory의 cli/protocol 파일을 각각 읽고 입력 trust boundary, bytes budget, ID relation, 생성 owner, 성공 의미를 기록한다. 일부 wrapper 이름만 보고 검토 완료로 표시하지 않는다.

### WP26.02 — 의미와 transport 분리

transport는 프레임/연결/일회 작업 수명을 담당하고 authorization은 현재 peer/method owner가 담당한다. stream preflight 결과를 await 이후의 영구 권한으로 저장하지 않는다. 새로운 resource category는 wire shape가 아니라 내부 descriptor에 둔다.

### WP26.03 — request freezing 보존

cache read의 absent/corrupt/unavailable를 유지한다. original frozen body를 읽을 수 없으면 새 입력을 조합하지 않는다. explicit command args가 기존 request intent와 충돌하면 재사용을 거절한다.

### WP26.04 — 응답과 receipt 검증

method별 result와 receipt identity를 실제 decoder에서 확인한다. terminal/nonterminal/REQUEST_NOT_FOUND를 분리한다. `receipt-supersession.test.mjs`가 CLI 캐시 증거라는 범위를 유지하고 batch receipt 복구 시험으로 오인하지 않는다.

### WP26.05 — 불필요 중복 제거

canonical JSON, request identity, derived ID/path와 method metadata는 기존 owner를 사용한다. 다른 trust boundary에서 재검증하는 코드는 중복이라는 이유로 제거하지 않는다. 새 abstraction은 실제 caller 수와 변경 범위 감소로 평가한다.

## 4. 회귀 시험 — production 경로를 사용한다

### V26A — framing 분할과 accepted task 수명

**준비:** 실제 Unix socket 또는 protocol owner를 실행하는 byte harness, 다양한 valid frame·stream 분할

**동작:** header/body/UTF-8 경계를 나누고 half-close/backpressure/timeout/잘못된 응답을 조합한다.

**관측해야 할 결과:** fatal framing 뒤 resync하지 않는다. 한 connection의 inflight budget을 지키고 연결 종료가 accepted artifact나 executing peer pin을 지우지 않는다.

**음성 대조군:** poison 뒤 새 frame 해석, partial write를 complete 처리, connection cleanup이 execution body를 지우는 control이 실패한다.

**lane / 현재 실행 상태:** `durable` / `NOT_RUN`.
### V26B — CLI frozen request와 명시적 미수락 증거

**준비:** 실제 RequestCache, 수정 전후 source file/HEAD, same request key와 정상/unknown lookup

**동작:** lookup failure/invalid receipt/confirmed notfound/terminal receipt 응답으로 CLI replay를 수행한다.

**관측해야 할 결과:** 미수락이 확인되지 않으면 재전송하지 않는다. 확인된 재전송은 최초 bytes/hash/params를 사용한다. 캐시의 terminal fact는 뒤늦은 nonterminal 관측으로 퇴행하지 않는다.

**음성 대조군:** catch 모든 lookup 오류를 notfound로 치환하거나 새 key/새 source로 resend하는 control이 실패한다.

**lane / 현재 실행 상태:** `durable` / `NOT_RUN`.
### V26C — 닫힌 wire와 encoded byte 한도

**준비:** 공개·내부 method 집합 및 가장 큰 정상 metadata/response, 비ASCII text

**동작:** 요청·응답 codec을 실제 frame encoder와 조합해 검사한다.

**관측해야 할 결과:** unknown fields/method/잘못된 id relation은 거절한다. 한도는 JSON encoding 이후 bytes 기준이며 잘린 결과는 complete로 보이지 않는다.

**음성 대조군:** 문자 수만 세거나 result를 as T로만 신뢰하는 control이 실패한다.

**lane / 현재 실행 상태:** `fast` / `NOT_RUN`.

시험 ID는 이 계획의 새 ID다. 같은 이름의 test 파일이 이미 존재한다고 가정하지 않는다. 기존 시험이 동일 계약을 검증하면 중복 파일 대신 확장하고, [테스트 원장](../verification/TEST-CATALOG.md)에 실제 파일·case 이름을 연결한다. 모형만 통과한 결과는 production 통합 증거가 아니다.

## 5. 금지하는 해결법

framing fatal 후 resync, lookup unavailable을 absence로 바꾸기, response cast만으로 validation 대체, 현재 HEAD로 frozen bundle 재생성, encoded overhead 없이 body byte만 제한, socket close로 accepted task 취소를 금지한다.

## 6. 호환성·실패·롤백

C0/C1. public method·field·request hash recipe는 유지한다. 실제 wire 변경이 불가피하면 C3로 별도 승인하고 이 작업에 숨기지 않는다.

작업 중간에 실행 자료가 없으면 `BLOCKED` 또는 `NOT_RUN`으로 기록한다. 코드 revert는 영속 상태 rollback과 같지 않다. DB·receipt·configuration generation을 바꾼 뒤 과거 바이너리를 재실행하려면 [호환성 표](../guide/COMPATIBILITY.md)를 먼저 적용한다.

## 7. 완료 판정과 다음 AI에게 넘길 것

모든 CLI/public/internal method가 request/response/key/effect category에 연결된다. byte segmentation·backpressure·frozen replay·result relation oracle가 실제 owner를 실행한다. protocol validation 강화로 깨진 fixture는 실제 유효성을 검토한 뒤 수정한다.

공통 필수 증거: 변경 전후 HEAD와 input digest, 변경 파일, Fact/Relation/Phase, 실제 시험 명령·종료 코드·skip 수, 원본으로 되돌렸을 때 깨지는 회귀 시험, 남은 미검증 범위. [handoff 양식](../templates/HANDOFF.md)을 채운다. `npm run typecheck`, `npm run build`, 관련 시험을 통과한 뒤 해당 commit의 architecture/inventory 상태를 확인한다. 정확한 종합 순서는 [검증 실행 규율](../verification/RUNBOOK.md)을 따른다.
