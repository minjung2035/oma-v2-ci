# D03 — 제품·systemd 배포 방식과 config locator를 일치시킨다

상태: **PROPOSED_WITH_RUNTIME_GATE**. 이번에 확인한 사실과 실행으로 확인할 가설을 구분한다.

## 확인한 사실

`superviseBroker`는 broker를 직접 child로 실행하며 --config를 전달한다. broker composition은 그 경로를 읽는다. Resident unit의 ExecStart는 society/agent만 전달하며 --config가 없다. 해당 unit은 고정 broker.service에 BindsTo/After를 갖는다. 따라서 사용자 지정 config locator를 unit이 전달받지 않는 것은 코드상 확인되고, foreground broker와 그 unit dependency의 실제 결합은 systemd 환경에서 검증해야 한다. [S39](../guide/SOURCES.md#s39), [S40](../guide/SOURCES.md#s40), [S42](../guide/SOURCES.md#s42).

## 즉시 결정할 부분

설정 경로와 state/run root는 startup composition이 소유하는 하나의 launch contract로 만든다. unit renderer, broker, runner가 independent default로 다시 유도하지 않게 한다. 내부 `ResolvedRuntimeLocation` 같은 결과에는 society/stateRoot/runRoot/configPath와 deployment mode를 포함할 수 있으나 credential은 넣지 않는다. 새로운 public wire field가 아니다.

config path를 unit에 넣을 때 shell 문자열 보간을 하지 않는다. systemd argv escaping 규칙에 따라 render하며 unit validation을 통해 effective argv/environment를 확인한다. 공백·비ASCII·최상위 symlink 허용 계약을 포함한다. XDG override를 사용한 제품과 systemd user manager의 환경이 다를 수 있으므로 정확한 state/run root 전달도 함께 검사한다.

## 배포 topology의 선결 시험

깨끗한 disposable user에서 기존 broker.service가 전혀 없는 상태로 제품 `oma`→broker→Resident를 시작한다. 등록·systemd LoadState/job 결과·cgroup·prepared batch를 관측한다. 기존 개발 환경의 설치된 unit에 의존한 성공을 인정하지 않는다.

이 시험이 실패할 때 권장 방향은 **deployment mode를 명시적으로 나누어 각각 참인 lifetime dependency만 render하는 것**이다. 제품이 소유하지 않는 broker.service를 제품 mode에서 은밀하게 시작시키면 Principal socketpair/tenure 소유권이 갈라질 수 있으므로 금지한다. systemd-managed mode의 BindsTo를 일괄 제거해서 해결하는 것도 금지한다.

## Mode별 요구

- systemd-managed broker: 기존 고정 broker.service dependency와 authentication/cgroup 관계를 유지한다.
- product-owned foreground broker: 기존 host↔broker private channel과 사회 lease를 유지한다. Resident가 실제로 존재하지 않는 broker.service에 의존하지 않도록 계약을 수정하되, broker/host 손실 뒤 revoke·Resident quiescence·새 broker startup fencing이 실제로 보장돼야 한다.
- source만으로 두 번째 mode의 동등한 teardown을 입증하지 못하면 그 mode의 Resident activation은 fail closed하고 `UNSUPPORTED_PROFILE` 또는 기존 적합한 오류로 표시한다. UI 기동 성공을 multi-agent runtime 지원 완료로 부르지 않는다.

이 결정은 protocol을 추정하거나 systemd FD 전달 방식을 즉흥 구현하라는 명령이 아니다. 필요한 변경이 새 서비스/권한 계약을 요구하면 WP01 ADR을 확장하고 실제 kernel evidence를 먼저 만든다. 이 gate를 통과하지 못한 상태는 전체 계획 DONE이 아니다.

## 종료 조건

지원한다고 선언한 모든 mode에서 단일 writer, 단일 Principal engine, config locator 일치, stale process fencing, 깨끗한 first-run bootstrap을 실제 환경에서 입증한다. 지원하지 않는 조합은 명시적으로 거절한다. 코드의 if 분기가 아닌 운영자의 관측 가능한 지원표를 남긴다.
