# D04 — Admission과 settlement의 자원 정책을 분리한다

상태: **PROPOSED**. 신규 DB entity·cost accounting을 추가하지 않는다.

## 기본 선택

public/internal method와 broker-owned recovery action을 `read`, `admit`, `settle`, `safety-control`로 분류한다. 인증·권한·무결성은 모든 경로에서 유지한다. storage quota는 새 소모를 수락하는 결정이며 terminal receipt 조회와 이미 발생한 효과의 완료 기록을 무조건 차단하지 않는다. [S06](../guide/SOURCES.md#s06), [S56](../guide/SOURCES.md#s56)

## 정책 표

| 분류 | admission 한도 초과 | 실제 filesystem/SQLite 공간 부족 |
|---|---|---|
| read/diagnostic | bounded read를 허용; stale/unknown을 명시 | 읽기 실패를 정확히 보고; view write를 성공 전제로 두지 않음 |
| admit | 새 작업 거절; 이미 수락된 same-key lookup과 분리 | 미수락/수락 불명을 구분하고 frozen data 보존 |
| settle | 제한된 증거 검증·정산만 허용 | 완료 실패를 성공으로 만들지 않고 evidence 보존·운영 복구 |
| safety-control | stop/revoke 등 안전 동작에 별도 최소 예산 | 일부 safety action 실패가 나머지 revoke/stop을 생략하지 않게 함 |

`host.reconcile` 전체를 무조건 quota-free로 지정하지 않는다. sweep은 정산뿐 아니라 새 물리 생성·activation도 할 수 있다. 내부 단계가 실제 수행할 action의 resource category를 선언해야 한다. Git recovery가 새 import/CAS를 필요로 하면 read-only settlement로 위장할 수 없다.

## 논리 quota와 물리 한도

현재 tree scan 기반 quota는 hard filesystem quota가 아니다. 외부 same-UID writer나 엔진 직접 쓰기를 hard cap으로 제어한다고 주장하지 않는다. cached diagnostic bytes를 admission의 정확한 증명으로 사용하지 않는다. admission용 예약은 bounded lease로 소유하고 완료/실패/연결 해제 시 중복 release 없이 정리한다. 전송 spool과 accepted artifact의 소유권이 바뀔 때 예약을 단순 소멸시켜 물리 bytes를 두 번 빠뜨리지 않는다.

첫 구현의 목표는 보수적인 preflight admission과 명시적 정산 reserve다. reserve 크기·설정 출처·max concurrent settlement·소진 시 행동을 명시하고 단위 시험한다. 새로운 숫자를 arbitrary constant로 흩뿌리지 않는다. reserve가 있다고 물리 ENOSPC에서도 항상 완료할 수 있다고 약속하지 않는다.

## 성능

진단용 전체 scan은 비동기 bounded walker로 이동하고 동시에 한 개만 수행한다. admission 정확성과 충돌하면 먼저 측정한 부하·허용 오차·보수적 상한을 결정한다. cache를 추가해 gate가 약해지는 성능 최적화는 금지한다. 안전한 budget을 입증하지 못하면 명시적으로 admission을 보류하며 event loop를 무기한 점유하지 않는다.
