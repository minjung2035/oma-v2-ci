# D06 — 성공·증거·liveness의 보장 범위를 제한한다

상태: **PROPOSED**. “10점”을 숫자 보증 대신 executable exit criteria로 바꾸는 결정이다.

## 보장 범위

이 계획은 기존 지원 profile에서 불변식 위반의 알려진 경로를 닫고, 미검토 파일을 작업별로 배정하며, 실제 환경 검증을 완료 조건으로 만든다. 모든 미래 입력·외부 시스템·임의 운영 환경에서 무결점을 보장하지 않는다.

알림 재전달은 도구 효과 재실행과 다르다. receipt 없음→execute라는 단순한 이분법은 금지한다. timeout은 실패 또는 outcome unknown을 표현할 수 있지만, 프로세스 death와 같은 뜻이 아니다. `close`, `exit`, cgroup death, inherited fence release는 별개다. 외부 자료 E01/E04와 source S44/S45가 이 구분의 근거다.

## Git no-op

현재 nonempty checks는 admission gate에서 막히므로 필수 검사 우회로 보고하지 않는다. no-op `base==candidate`에서는 현재 ref가 같다는 것만으로 해당 operation의 final authorization 수행을 증명할 수 없다. 권장 결정은 no-op recovery에서 효과가 없는 점을 유지하면서 현재 policy/stop/authority를 다시 확인하고, 기존 오류 분류로 정산하는 것이다. 이는 정상 execute의 no-op 검증과 의미를 맞추기 위한 C1/C2 계약 정리이며 ADR 확정 전 임의로 바꾸지 않는다. 실제 CAS가 이미 일어난 non-no-op recovery는 과거 효과의 정산으로 구분한다. ## Safety와 liveness

unknown을 안전하게 보존하는 것만으로 제품 완성이 아니다. 각 blocked 상태는 operator가 이유와 대상 identity를 볼 수 있어야 한다. 재관측 가능한 것은 bounded retry, irrecoverable/충돌은 명시적 repair 경로가 있어야 한다. 반대로 progress를 위해 stale authority를 허용하거나 evidence를 삭제해서는 안 된다.

## 지원표

현재 rootfs='/' explicit unconfined 선택, OMA 비용 상한 미집행, 실행형 Git check gate는 문서화된 정책이다. 이 계획으로 자동 변경하지 않는다. 새 기능·다른 OS·다른 provider·schema migration은 별도 scope다. 기존 기능이 살아 있는지 실제 entry smoke가 보여야 한다.

## 완료의 두 층

**구조 완료:** owner/판정표/타입/cleanup이 연결되고 해당 production 회귀 시험이 통과함.

**운영 검증 완료:** 지원한다고 선언한 systemd/cgroup/Pi/FS profile에서 source-bound 실험이 통과함. power loss를 주장하면 process SIGKILL뿐 아니라 별도의 VM/storage 시험이 필요함.

로컬 시험만 끝나면 첫 번째 일부만 달성한 것이며 최종 WP32를 DONE으로 표시하지 않는다. 테스트 수 증가·LOC 감소·architecture 0 findings는 보조 지표이고 실제 불변식 보장의 대체물이 아니다.
