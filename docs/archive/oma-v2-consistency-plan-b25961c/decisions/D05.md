# D05 — 설정 적용 시점과 프로젝트 identity의 의미

상태: **PROPOSED**. 표시와 실행이 같은 질문에 답하도록 한다.

## 설정 편집의 의미

현재 Worker profile은 initialResidents만 수정하는 반면 next-activation으로 표시된다. 기본 seed가 0이면 저장할 선택 자체가 없다. 이를 숨겨진 default-worker-profile 기능으로 확장하지 않는다. 우선 기본 선택은 필드를 **Bootstrap worker profile**로 명시하고, seed가 0이면 적용 대상이 없다고 표시하거나 선택을 disabled로 두는 것이다. 향후 childProfile 편집은 delegation을 바꾸는 별도 action으로 다루며 이 field에 끼워 넣지 않는다. [S15](../guide/SOURCES.md#s15), [S19](../guide/SOURCES.md#s19)

| 편집 | 의미·기본 적용 시점 | 주의 |
|---|---|---|
| Principal model | 다음 Principal session | 실행 중인 engine이 이미 읽은 값을 바꾸지 않음 |
| Worker model | runner의 다음 activation에 현재 profile 모델 설정 반영 | accepted capability/resource spec까지 재해석하지 않음 |
| Bootstrap workers/profile | 최초 bootstrap 이전 seed | 이미 만들어진 society에서는 기존 agent를 자동 삭제/추가/재설정하지 않음 |
| Worker limit | 다음 broker policy 재시작 시점의 limit | lineage/seed 교차 제약 만족; 기존 agent 강제 종료하지 않음 |
| Role extensions/prompt/tool surface | 각 역할의 다음 engine 시작 | spawn 직전 자산 검증 유지; live reload라고 표시하지 않음 |

형식상 저장됐음, 전체 config로 검증됐음, 다음 실행에 선택됐음, 실제 현재 프로세스에 적용됐음은 다른 사실이다. UI는 이를 구분한다. 모든 config 변경을 전체 integration policy 변경으로 해석할지 여부는 기존 규범과 대조해 명시하고 hash recipe를 몰래 변경하지 않는다.

## 프로젝트 identity

기본 society 이름은 사람이 읽을 slug와 normalized real project path의 digest를 결합한다. 전체 이름은 기존 32자 문법을 지켜야 한다. 제안 예시는 slug prefix 15자 + '-' + 16 hex다. 이것은 수학적인 무충돌 보장이 아니므로 저장된 full source binding과 충돌 검사를 함께 사용한다.

이름 유도는 pure 함수로 유지한다. realpath 관측은 entry/filesystem adapter에서 한 번 수행하고 normalize된 값을 넘긴다. Windows 지원을 새로 암시하지 않는다. 현재 Linux profile을 대상으로 한다. 같은 basename, punctuation 정규화, 긴 prefix, 비ASCII 이름, symlink 별칭을 모두 시험한다.

기존 slug-only state가 있으면 자동으로 새 디렉터리로 옮기지 않는다. 명시적 --society는 그 society를 선택한 의사지만 source binding의 불일치를 숨겨도 된다는 허가는 아니다. 기본 동작은 mismatch를 설명하고 mutation 전에 거절한다. 의도적 프로젝트 변경은 별도의 operator migration으로 한다.

새 binding metadata를 저장하면 그 형식·권한·fsync·backup 범위·구버전 읽기 영향을 C2 ADR에 명시한다. accepted plan 안의 경로와 lease 이름 때문에 stateRoot 이전은 단순 rename이 아니다.
